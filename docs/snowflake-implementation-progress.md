Controlled network reproduction establishes the transport fault: two fresh containers reuse the same bridge IP and source port against the same `host.docker.internal` server. The first request succeeds; the second times out in TCP connect. Changing the source port succeeds; immediately reusing that port fails again. This isolates Docker Desktop host-forwarding tuple reuse; the original failed SYN's source port was not logged, so its exact number cannot be recovered.
