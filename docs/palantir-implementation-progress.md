Baseline 293a1de. Task 10 of the existing SDK plan; user explicitly confirmed SuperRepo/approved enrollment CLI are not available and must remain gated.

Ruling: keep `palantir.superrepo/v1` unavailable for native publishing until enrollment-specific CLI provenance, supported commands/output contracts, OSDK materialization and credential-free build separation are proven. Do not invent CLI flags, install third-party lookalike CLIs or pass credentials to repository-controlled build scripts. Cost: source-to-product publishing is not delivered without that enrollment prerequisite.

Ruling: implement a distinct, explicit `palantir.marketplace/v1` profile using documented Foundry REST v3 preview installation/job APIs. Build packages a pinned already-published product-version deployment descriptor; it does not compile/publish SuperRepo code and is not a fallback for that kind. Cost: a producer must supply an approved native product version before deployment.

Ruling: require operator opt-in to preview APIs, exact approved product/version pairs and approved frontend origins. Native products may change resources according to their published contents; operator approval is authorization, not a semantic product audit. This adapter calls no Ontology mutation API and does not supply an installation Ontology override. The existing Ontology is used only for read-only schema/data verification. Cost: products requiring Ontology creation/migrations or credential-valued inputs are outside the initial profile.

Ruling: create installation metadata separately from the asynchronous installation job. Persist each accepted RID before follow-up requests. Job success, pinned latest target version, read-only object access and an exact static frontend health-asset digest are separate proofs. HTTP 200 metadata or a published product alone cannot establish app health. No mutating retry, implicit adoption, abort/delete/rollback or silent latest-version selection. Cost: uncertain native acceptance retains its claim for manual recovery; frontend domain approval/activation remains a native prerequisite.
